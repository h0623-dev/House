# 로드헤이븐 웹 플레이 배포

v0.19.0은 공통 속도 2배로 iPhone 홈 화면 앱과 정적 웹 호스팅에서 실행할 수 있습니다. [iPhone 설치 안내](IOS.md)를 참고하세요. 웹 버전 저장 데이터는 해당 브라우저에 보관되며 Android 앱과 별도로 관리됩니다.

## 준비된 파일

- `artifacts/web-play/`: 웹 서버에 올릴 정적 사이트. `index.html`, `assets/`, `fonts/`, `manifest.webmanifest`, `sw.js`, `web-update.json`, `.nojekyll`을 함께 배포합니다.
- `artifacts/road-haven-0.19.0-web.zip`: 위 디렉터리 내용이 압축 파일의 최상위에 들어 있는 배포용 ZIP입니다.
- `artifacts/road-haven-0.19.0-play.html`: 코드·스타일·폰트를 모두 포함하는 단일 HTML입니다. 재생성은 `node scripts/build-standalone.mjs`로 할 수 있습니다.

`fonts/OFL-NotoSansKR.txt`와 `fonts/OFL-DMSans.txt`는 포함된 글꼴의 라이선스입니다. 배포할 때 함께 보관하세요. 생성된 `artifacts/` 디렉터리는 소스 저장소의 Git 추적에서 제외됩니다.

v0.18 최종 정적 사이트의 30개 파일과 웹 ZIP의 정확한 파일 목록·전체 바이트를 검증했습니다. 같은 소스의 Android 내장 웹 파일 26개 및 단일 HTML과 함께 수정하지 않는 QA 사본 `v018-r2`에 보관했습니다. 총 57개 파일은 실제 로컬 HTTP 응답과도 바이트가 같습니다. 단일 HTML에는 외부 정적 파일 참조가 없으며 웹 전용 설치·패치 파일은 네이티브 업데이터에서 제외합니다. 실제 Service Worker의 오프라인 재실행과 안전한 적용은 [v0.18 검수](research/v018-playtest-results.md)에 기록합니다. 이전 결과는 [v0.17 검수](research/v017-playtest-results.md)에 보관합니다.

## v0.19 속도 조정

공통 속도를 3배에서 2배로 낮춰 이동·작업·생산·작물 성장·전투 시간이 직전 버전의 약 1.5배가 됩니다. Lv.1 정수소 생산은 11.25초(목록 표시 11.3초), 물을 준 당근은 45초입니다. 씨앗·자원·보상과 저장된 게임 분의 완료 시각은 유지하며 남은 시간을 새 속도의 실제 초로 표시합니다. iPhone·웹은 기존 자동 패치로 받습니다.

최종 빌드의 단위 테스트 206개와 네 가지 브라우저 검사 2,119개를 통과했습니다. 실제 v0.18 → v0.19 자동 패치와 저장 보존의 범위는 [v0.19 검수](research/v019-playtest-results.md)에 기록합니다.

## 정적 사이트 다시 빌드하기

저장소 루트에서 실행합니다. 의존성이 설치되어 있지 않다면 먼저 `npm ci`를 실행합니다.

```bash
npx --no-install tsc --noEmit
npx --no-install vite build --base=/House/ --outDir artifacts/web-play --emptyOutDir
touch artifacts/web-play/.nojekyll
cp node_modules/@fontsource-variable/dm-sans/LICENSE artifacts/web-play/fonts/OFL-DMSans.txt
node --input-type=module <<'JS'
import fs from 'node:fs';
import { createPwaRelease } from './scripts/web-pwa-plugin.mjs';
const {version}=JSON.parse(fs.readFileSync('package.json','utf8'));
const {versionCode}=JSON.parse(fs.readFileSync('release-version.json','utf8'));
await createPwaRelease('artifacts/web-play',{version,contentVersion:versionCode,base:'/House/'});
JS
python3 - <<'PY'
import json
from pathlib import Path
from zipfile import ZIP_DEFLATED, ZipFile

version = json.loads(Path('package.json').read_text())['version']
root = Path('artifacts/web-play')
with ZipFile(f'artifacts/road-haven-{version}-web.zip', 'w', ZIP_DEFLATED) as archive:
    for source in sorted(root.rglob('*')):
        if source.is_file():
            archive.write(source, source.relative_to(root))
PY
```

Vite의 `--base=/House/` 옵션은 이번 게시 경로에 맞춰 HTML의 JavaScript/CSS, CSS의 이미지·폰트 경로를 `/House/` 아래로 생성합니다. `index.html`, `assets/`, `fonts/`를 그 하위 경로에 함께 올립니다. 다른 호스팅 경로에서는 manifest의 `id`·`scope`·`start_url`도 해당 경로에 맞추고 `VITE_PWA_ENABLED=1`과 `--base`로 다시 빌드하세요. `/House/` 빌드는 기본으로 PWA를 생성하고, 일반 네이티브 `/` 빌드는 worker·웹 descriptor·설치 태그를 제외합니다. 최종 폰트 라이선스·`.nojekyll` 추가 뒤 `createPwaRelease`로 목록을 다시 생성하여 실제 게시 파일과 해시를 맞춥니다. 별도 소스 수정이나 CSS 경로 치환은 필요하지 않습니다.

## GitHub Pages 설정

공개 주소는 아래와 같습니다. 후속 배포마다 HTTPS 응답과 현재 정적 빌드의 파일 해시를 비교합니다.

`https://h0623-dev.github.io/House/`

GitHub Pages를 사용할 수 있는 저장소와 설정 권한이 필요합니다. `artifacts/web-play/`의 내용이 원격 저장소의 `gh-pages` 브랜치 최상위에 게시된 뒤, [저장소의 Pages 설정](https://github.com/h0623-dev/House/settings/pages)에서 다음과 같이 설정합니다.

1. **Build and deployment → Source**: **Deploy from a branch**
2. **Branch**: **gh-pages**, 폴더: **/(root)**
3. **Save** 후 Pages 배포 완료를 확인합니다.
4. GitHub가 표시하는 사이트 주소를 일반 브라우저에서 열고 새 게임과 전투 입장을 확인합니다.

설정에 표시되는 실제 주소와 배포 상태를 기준으로 운영하세요. 소스가 있는 `main` 브랜치를 그대로 지정하면 Vite 소스가 정적 게임으로 빌드되지 않습니다. 후속 웹 업데이트는 위 명령으로 다시 빌드하고 정적 사이트 내용을 배포 브랜치에 갱신합니다. 웹 사이트의 Pages 활성화와 Android 업데이트 파일 배포는 별개입니다. Android의 공개 `update.json`과 버전별 APK는 같은 `gh-pages`의 raw GitHub 주소를 사용하며 [Android 안내](ANDROID.md)에 기록했습니다.

## 기존 배포에서 확인한 범위

- 정적 파일을 로컬 서버의 `/House/` 경로 아래에 배치하고 360×740 및 390×844 모바일 Chromium에서 인게임 아이콘 버튼과 작은 하단 제목, 실제 밭 터치 선택, 심기·급수·수확, 벌목·확장, 3개 전투 지역, 저장 복구를 확인했습니다.
- 남녀 일러스트·작업 포즈와 세계·동물·좀비·전투·아이템 그림을 포함하여 JavaScript, CSS, 이미지, DM Sans 및 Noto Sans KR 폰트 요청이 모두 `/House/` 아래에서 성공했습니다. 실패한 요청과 실행 오류는 없었습니다.
- 정적 배포 파일에서 개발 서버 주소, Vite 개발 클라이언트, 소스맵 참조 및 일반적인 토큰·개인키 형식이 발견되지 않았습니다.
- 단일 HTML은 로컬 HTTP로 열어 농사·벌목·확장·전투 승리와 저장·재접속을 확인했습니다. 로드 후 오프라인 상태에서도 동작했고 외부 리소스를 요청하지 않았습니다.
- 테스트 환경의 관리형 Chromium은 `file://` 탐색을 차단하므로 단일 HTML을 파일로 직접 여는 방식은 이 환경에서 검증하지 못했습니다.


v0.18부터 HTTPS 웹과 iPhone 홈 화면 앱은 실행·복귀·재연결 시 새 패치를 확인합니다. 파일을 모두 준비한 뒤 작업·전투를 마치고 안전한 홈에서 저장하여 자동 적용하며, 실패하면 이전 버전으로 계속 플레이합니다. 첫 캐시 준비 뒤에는 오프라인 재실행도 가능합니다. 단일 HTML은 포함된 버전을 실행합니다. Android의 저장·업데이터와 웹은 별도입니다.

## v0.17 편성·시설·트럭 성장

6종 동료 중 해금된 1–3명을 골라 전투에 출발합니다. 보리·나비는 처음부터 함께하며 데크 Lv.2/3/4/5에서 루루·루비·도도·모모가 순서대로 해금됩니다. 동료별 역할·체력·기술·경험치와 편성을 같은 브라우저 저장에 보관합니다. 앞줄 방어, 빠른 공격, 치유, 원거리, 도발, 범위 공격을 조합하며 살아 있는 참가 동료가 전투를 이어갑니다.

시설은 Lv.5까지 개선하며 새 생산의 수량과 속도가 높아집니다. 정수소 새 생산은 Lv.1에서 7.5초, Lv.5에서 약 3.8초입니다. 기존 생산은 저장된 완료 시각을 그대로 이어갑니다. 동료의 쉼터는 레벨당 공격력 4%, 도로 감시소는 레벨당 받은 피해 3%를 개선하며 같은 종류 시설의 최고 레벨 하나만 효과에 반영합니다.

데크는 Lv.8까지 넓혀 시설 16자리와 밭 수용량 24칸을 엽니다. 밭은 개간 비용을 사용해 한 칸씩 늘립니다. 건설·확장 목록은 맵을 가리지 않는 작은 패널로 보여 주고 트럭과 새 공간을 함께 확인합니다. 시설·비용은 확정할 때 한 번 반영하며, 캐릭터가 해당 자리로 이동해 짧은 마무리 작업을 합니다. 기존 지도 드래그·핀치와 공통 3배 속도를 유지합니다.

네 게임 공식 스토어, Clash 공식 UI 설명, 쿠키런 공개 개발자료와 실제 연 홍보 이미지의 비교 근거는 [v0.17 시스템 비교](V0.17-SYSTEMS-COMPARISON.md)에 기록합니다. 참고 게임 영상은 접근 제한으로 시청하지 못했으며 동영상 시청·프레임 분석 결과로 표현하지 않습니다.

## v0.16 동물 아군

원정에서는 강아지 보리와 고양이 나비가 아군으로 싸웁니다. 각 동물의 체력과 스킬을 확인하며, 한 동물이 쓰러져도 다른 동물이 살아 있으면 전투를 이어갑니다. 전투 후 개별 체력은 같은 브라우저 저장에 보관하고, 승리한 원정에 출발한 동물은 경험치를 받습니다. 트럭의 휴식으로 동물도 회복하며 성장 상태는 다음 원정에 이어집니다.

기존 마을·작물·시설·자원을 유지하며, 기존 저장에서 동물 기록이 없으면 보리·나비를 초기 체력과 경험치 0으로 시작합니다. 웹 저장은 Android 앱의 저장 및 자동 패치와 별개입니다.

## v0.15 공통 속도

이동·사다리·작업·작물 성장·시설 생산·전투가 이전의 3배 속도로 진행됩니다. v0.15 도입 당시 정수소 생산은 15초, 물을 준 당근 성장은 30초였으며 남은 시간을 실제 초로 표시했습니다. v0.17에서 새로 시작하는 시설 생산은 위의 개선 규칙을 사용합니다. 입력·카메라 조작은 기존대로 유지합니다.

## v0.14 마을 화면과 반복 생활

기본 화면은 트럭 마을을 읽기 쉬운 크기로 보여 주고, 하단은 우리 트럭·건설·농장·탐험·창고 5개 메뉴를 사용합니다. 추가 기능은 마을 메뉴에 모읍니다. 현재 성장 목표 한 줄을 누르면 필요한 활동으로 바로 이동하거나 달성 보상을 받습니다. 전체 목표와 자세한 보상은 마을 메뉴의 성장 목표에서 확인합니다.

‘지도’를 누르면 확대·축소·기본 보기·화면 이동 조작을 펼칩니다. 빈 공간 드래그와 두 손가락 조작은 유지하며, 밭 위에서 작업 없이 이동하려면 펼친 지도 조작의 화면 이동을 켭니다. 익은 밭·물이 필요한 밭·빈 밭을 누르면 수확·물 주기·씨앗 선택 또는 선택한 씨앗의 연속 심기로 이어집니다.

시설 위의 생산 말풍선으로 생산을 시작하고, 완료된 자원·수량 말풍선으로 바로 수령합니다. 시설 본체를 선택했을 때는 작은 조작판에서 개선·이동·교체를 할 수 있습니다. 농사·채집 중에도 작물과 시설은 자라며 다른 마을 메뉴를 읽고 완료 생산품을 수령할 수 있습니다. 예약된 농사 물자를 쓰는 신규 생산·개선·의뢰 납품은 현재 작업을 마친 뒤 실행합니다.

마을 의뢰는 물·식량·목재를 이웃에게 보내고 건설 재료·경험치를 받는 세 요청을 순서대로 반복합니다. 보유/필요 물자·보상과 물자를 모으는 안내를 함께 보여 줍니다. 잠시 닫았다 돌아온 마을은 최대 70초의 실제 부재 시간을 작물·시설 진행에 반영하지만 수령은 직접 해야 합니다.

데크 확장 창에는 시설 자리·밭 수용량의 현재/다음 수치와 기본 밭 1칸, 새로 해금되는 시설을 보여 줍니다. 작업 완료 시 마을 시간이 중복 진행되지 않으며 일시정지한 동안 완료되어도 생산 시계는 진행하지 않습니다.

조사에서 실제 읽은 공략·정지화면·공개 도구 문서와 접근하지 못한 영상은 [v0.14 비교 문서](V0.14-COMPARISON.md)에 기록합니다. 해당 버전의 최종 검수는 새 정적 빌드와 공개 응답이 일치하는지 검사하고, 브라우저 자동화·Android 호스트 검증·실제 기기 검증 범위를 구별합니다.


## v0.11 조작 확인

지도 오른쪽의 확대·축소·배율 버튼과 두 손가락 조작은 홈·농장·벌목장·작업 중 모두 사용할 수 있습니다. 배율 버튼을 누르면 기본 크기와 위치로 돌아옵니다. 농사 도구나 건설·시설 창을 열면 지도 조절 버튼은 다른 행동 버튼을 가리지 않도록 가로로 배치합니다.

채집은 캐릭터가 사다리를 내려가 재료를 줍고 가방에 담은 뒤 귀환하는 순서이며, 이동과 작업의 진행률을 화면에 표시합니다. 성장 목표 창에는 현재 할 일 하나와 진행도·행동·보상이 먼저 나오고 전체 24개 목표는 접힌 목록에서 확인합니다.


## v0.12 화면 이동

빈 공간을 한 손가락으로 끌면 지도가 움직입니다. 농사 도구를 고른 상태에서는 밭 위에서 시작하는 쓸기가 기존 연속 작업으로 동작하므로, 밭 위에서도 화면만 움직이려면 ‘지도 조작’을 펼친 뒤 ‘화면 이동’ 버튼을 켭니다. 이동 모드에서는 밭 탭으로 씨앗이 소비되거나 시설이 선택되지 않습니다. 다시 누르거나 농사 도구를 고르면 작업으로 돌아갑니다.

건설 중에도 화면을 끌어 부지를 찾을 수 있습니다. 수동으로 움직인 시점은 채집·벌목 중에 자동으로 되돌아가지 않으며, ‘기본 보기’나 하단 ‘우리 트럭’·‘농장’ 메뉴로 카메라를 되돌릴 수 있습니다.


## v0.13 텃밭 확장

게임 화면의 ‘밭 확장’에서 현재 밭 수와 데크가 허용하는 수, 다음 밭의 목재·고철 비용을 확인합니다. 재료를 사용해 한 칸씩 늘릴 수 있으며, 가능한 밭 수는 데크 단계의 3배입니다. v0.13 도입 당시 최대 18칸이었으며 v0.17에서는 데크 Lv.8에 맞춰 최대 24칸입니다. 현재 데크의 밭을 모두 만들었으면 트럭 확장으로 더 많은 농사 공간을 엽니다.

기존 밭과 작물은 유지되며, 새 밭에서도 씨앗 선택·연속 심기·물 주기·수확을 이어서 사용할 수 있습니다.

시설 생산과 작물 성장에 남은 시간, 씨앗 인벤토리의 성장 시간, 사냥 예상·경과 시간은 초로 표시합니다. 현재 2배 속도에서 게임 시간 76분은 실제 속도로 환산해 19초로 보이며, 기존 생산·성장 기간과 저장 정보는 유지합니다.
